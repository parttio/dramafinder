# DramaFinder 2.0.2

DramaFinder 2.0.2 adds the helpers that tests written with
[Mopo](https://github.com/viritin/mopo) (`in.virit:mopo`) relied on and DramaFinder
lacked, and a guide for moving such tests over. It makes the Spring test sign-in
usable without `SpringPlaywrightIT`, makes uploads wait for the upload request,
and fixes lookups that matched the wrong component in nested layouts.

## Upgrading from 2.0.1

A few fixes change what an existing test sees. Each makes the element behave as a
user's action would, so a test that passed only because of the old behaviour may
now fail:

- **Date pickers type as a user does** (#242, #243). `DatePickerElement.setValue`
  fills the input and presses Enter instead of dispatching a synthetic `change`
  event, so text the picker can't parse stays invalid, as it would for a user.
  `DateTimePickerElement.setDate` and `setTime` type into their half, press Enter
  and leave the field.
- **Combo box `clear()` clears the selection** (#245). On `ComboBoxElement` and
  `MultiSelectComboBoxElement` it clicks the clear button when it is shown, and
  otherwise empties the input (combo box) or deselects every item (multi-select).
  Before, it only emptied the text input.
- **Dialog queries match open dialogs only** (#244). `find(page,
  DialogElement.class)` ignores closed `vaadin-dialog` elements still in the DOM,
  and `isOpen()` reads the `opened` attribute, the same state `assertOpen()`
  checks.
- **Lookups stay inside their own component** (#240, #246, #247). `MenuBarElement`
  and `MenuElement` items, `TabSheetElement.getContentLocator()` and
  `DetailsElement`'s summary and content no longer match the same parts of a
  component nested inside them.

## New features

### Fail a test on browser errors (#249)

`ClientSideErrors` records what the browser reports while a test drives a page:
messages logged with `console.error` and uncaught exceptions.

```java
ClientSideErrors errors = ClientSideErrors.track(page);
find(page, ButtonElement.class).withText("Save").single().click();
errors.assertNone();
```

- `track(Page)` starts recording; anything logged before the call is not seen.
- `getErrors()` returns the recorded messages, oldest first.
- `assertNone()` fails with an `AssertionError` listing every recorded error.
- `clear()` forgets the errors so far, e.g. after asserting an expected one;
  `stop()` stops recording.

It reads the browser console, so it works in production mode too, unlike a check
of the Vaadin dev-tools error panel. To check every test of a class, track in an
overridden `setupTest()` (after `super.setupTest()`) and call `assertNone()` in
`cleanupTest()` (before `super.cleanupTest()`).

### Grid: which rows are scrolled into view (#249)

- `GridElement.getFirstVisibleRowIndex()` and `getLastVisibleRowIndex()` return
  the first and last row at least partially visible between the header and
  footer, without scrolling. They return `-1` when no row is in view, e.g. on an
  empty grid.
- `assertFirstVisibleRow(int)` and `assertLastVisibleRow(int)` retry until the
  grid shows the expected row, e.g. after `scrollToEnd()`.

`VirtualListElement` already had methods with these names.

### Combo box: select the first match of a filter (#249)

`ComboBoxElement.filterAndSelectFirstItem(String filter)` types the filter and
clicks the first item the drop-down offers for it, whatever its label. It fails
with an `AssertionError` naming the filter when no item matches. Use it when the
filter alone identifies the item, such as a unique code; when the label is known,
`filterAndSelectItem(filter, label)` stays the safer choice, because a change in
item order cannot select a different item unnoticed.

### Date time picker: read each sub-field (#249)

`DateTimePickerElement.getDateValue()` and `getTimeValue()` return the text of the
date and time inputs as the user sees it, formatted for the component's locale.
They pair with the existing `assertDateValue(String)` and `assertTimeValue(String)`.

### Upload: wait for the upload request, upload in-memory content (#238)

`UploadElement.uploadFiles(Path...)` used to wait only for Vaadin to go idle,
which does not cover the separate upload request, so it could return before the
application's upload listener ran. It now returns once every file has finished
(succeeded, failed or been rejected) and the round trip that follows is done. A
server error finishes the file too: the method returns and the row shows the
error.

`uploadFiles(FilePayload...)` uploads files built in memory, without writing them
to disk first.

### Menu bar: sub-menus, item labels and closing (#240)

- `MenuBarElement.getItemLabels()` and `MenuElement.getItemLabels()` list item
  labels in display order: each item's own text, or its `aria-label` when it has
  none.
- `openSubMenu(String)` on a sub-menu returns the nested sub-menu it opens, so a
  test can walk several levels.
- `MenuBarElement.close()` closes every open sub-menu and waits until they are
  gone.
- `MenuItemElement` covers sub-menu items (`vaadin-menu-bar-item`) as well as
  top-level buttons, and implements `HasEnabledElement`.

### Date time picker: type, clear and reach each half (#243)

- `DateTimePickerElement.typeText(String date, String time)` types into both
  halves, then leaves the field.
- `clear()` empties both halves, so the value becomes `null` on the server.
- `getDatePicker()` and `getTimePicker()` return the two halves as
  `DatePickerElement` and `TimePickerElement`.

### Smaller additions

- `DetailsElement.toggle()` opens closed details or closes open ones by clicking
  the summary (#247).
- When an assertion on a typed query fails, the message names what was searched
  for, e.g. `vaadin-button with text "Save"` (#250). Custom queries can add their
  own wording with `refine(String description, UnaryOperator<Locator>)`.

### Sign in without extending SpringPlaywrightIT (#236)

The test sign-in of 2.0.1 is now public API for code that manages its own
Playwright `BrowserContext`, such as a JUnit extension or a framework built on
DramaFinder:

```java
@SpringBootTest(webEnvironment = RANDOM_PORT)
@Import(TestLoginConfiguration.class)
class OrdersIT {
    @Autowired ApplicationContext applicationContext;

    @Test
    void adminSeesOrders() {
        SpringTestLogin.signIn(applicationContext, browserContext, baseUrl, "alice", "ADMIN");
        // ...
    }
}
```

- `TestLoginConfiguration` is public: importing it registers the sign-in endpoint
  in the test's Spring context, and nothing when Spring Security is absent.
- `SpringTestLogin.signIn(..., username, roles...)` signs in the user
  `@WithMockUser` would create; `signIn(..., Authentication)` signs in any
  authenticated user; `signInTestUser(...)` signs in the test's
  `@WithMockUser` / `@WithUserDetails` user and returns whether there was one.
- `SpringTestLogin.signInUrl(...)` returns a one-time URL that signs in whichever
  browser requests it, for browsers DramaFinder does not drive (e.g. Selenium).

## Fixes

- `TabsElement.getTab(label)` finds a tab by the label `getTabLabels()` returns,
  including the `aria-label` of a tab with no text (#241).
- `DetailsElement.getContentLocator()` finds the content while the details are
  closed too (#247).

## Documentation

- **Documentation site** (#237): the guides, specifications, release notes, API
  reference and Javadoc are published at <https://parttio.github.io/dramafinder/>.

- **Migrating from Mopo** (#249): `MIGRATION-FROM-MOPO.md` maps every Mopo call
  (`Mopo`, `GridPw`, `ComboBoxPw`, `DatePickerPw`, `DateTimePickerPw`) to its
  DramaFinder equivalent, written with typed `find(...)` queries. It also lists
  where behaviour differs:
  - Element actions wait for the server round-trip, so `mopo.click(..)` and
    `waitForConnectionToSettle` go away and there is no fixed 500 ms pause.
  - `GridElement.select(int)` clicks the row like a user, where Mopo called the
    grid connector directly.
  - Grid header lookups match the whole header text.

  The jar ships the guide at `META-INF/dramafinder/MIGRATION-FROM-MOPO.md`, and it
  is on the documentation site under *Getting started*.
- The `vaadin-playwright-test` skill's bundled `api-reference.md` lists the new
  methods, `ClientSideErrors`, `SpringTestLogin` and `TestLoginConfiguration`.
