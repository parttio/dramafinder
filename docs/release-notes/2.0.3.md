# DramaFinder 2.0.3

DramaFinder 2.0.3 makes `GridElement` and the typed queries cheaper to use: grid
reads take far fewer browser round trips and waits, and the CSS-expressible query
filters compile into a single selector.

## Upgrading from 2.0.2

- **`GridElement.getHeaderCellContents()` on grouped headers** (#263). It returns
  one text per visible column, read from the first header row, where a joined
  group cell repeats for each column it spans. Before, a grid with column groups
  threw `IllegalStateException`. `getFooterCellContents()` behaves the same way.
- **`GridElement.findRow(int, int)` is deprecated** (#266). The header row count
  is no longer needed; use `findRow(int)`.
- **Typed queries search the light DOM** (#276). `find(page, X.class)`, and the
  factories built on it such as `getByLabel`, leave out elements inside a shadow
  root: the internals Vaadin components render themselves, like the
  `vaadin-input-container` of every text field. Flow puts a component's children
  in the light DOM, inside overlays too, so ordinary views are unaffected.
  Components an application renders in a shadow root of its own (a Lit
  template) need `find(page, X.class).includingShadowDom()`.
- **`null` passed to an assertion helper asserts absence** (#257), as documented:
  `assertPlaceholder(null)` (also on `SelectElement`),
  `assertAllowedCharPattern(null)`, `ProgressBarElement.assertValue(null)` and
  `IntegerFieldElement` / `NumberFieldElement` `assertMin(null)` /
  `assertMax(null)`. Before, most of them passed whatever the value was, and
  `assertMax(null)` asserted the opposite of `assertMin(null)`.
- **Breadcrumb item lookups no longer take the first match** (#259).
  `BreadcrumbsElement.getItem(String)` and `BreadcrumbsItemElement.getByText`
  fail with a strict-mode error when two items show the same text; use
  `getItem(int)` for one of them.

## Faster grids (#262)

Measured on warm runs in headless Chromium:

| Operation | 2.0.2 | 2.0.3 |
|---|---|---|
| `getHeaderCellContents()`, 3 columns | ~200 ms | ~10 ms |
| `getColumnTexts()`, 100 loaded rows | ~410 ms | ~50 ms |
| `getColumnTexts()`, 300 lazy rows, page size 20 | ~3.7 s | ~1.5 s |
| `findRow(i).getCell(c).getText()`, rendered row, 100-row grid | ~120 ms | ~22 ms |
| select + deselect a row | ~320 ms | ~250 ms |

- `getHeaderCellContents()` / `getFooterCellContents()` read every column in one
  script (#263).
- `getColumnTexts()` runs its whole page loop in the browser and waits only while
  the grid loads a page from the server (#264).
- `findRow()` returns a row already in view without scrolling or waiting (#266).
- `getCell()` and the row click and select paths pick their target in one script
  (#267).
- `GridElement` no longer leaves element handles behind in the page (#265).

## Faster queries (#277)

`withId`, `withClassName`, `withAttribute` and `withPlaceholder`
compile into one CSS selector while no other filter came first, instead of
intersecting the candidates with page-wide locators that Playwright re-ran on
every use of the element. `withTestId` keeps using Playwright's `getByTestId`,
so a test id attribute changed with `Selectors.setTestIdAttribute` still works
(see ADR 0002).

`withAccessibleName` and `withAccessibleNameContaining` (#278) run Playwright's
label engine once per resolution instead of twice: a field's own input is
mapped to its field from the labelled elements, where before a second pass
searched every candidate's subtree, shadow DOM included. On a 2,000-element
page a call through `find(page, GridElement.class).withAccessibleName(..)`
drops from ~9 ms to ~4.7 ms.

## New API

- **Components without an element class** (#269, #273): `VaadinElement.of(locator)`
  wraps any element in a `GenericElement`, and `ElementQueries.find(page, "my-tag")`
  (and `find(locator, "my-tag")`) queries by tag, with the label, text and
  placeholder filters next to the ones every query has.
- `VaadinElement.getTagName()` (#270); `HasStyleElement.getInlineStyle(..)` and
  `getComputedStyle(..)` (#271).
- `ElementQuery.withTheme(variant)` (#274) and
  `PlaceholderFilters.withPlaceholderContaining(..)` (#275).
- `RouteNavigation.currentPath(..)`, `isAt(..)` and `queryParameter(page, name)`
  (#279), with `currentPath()`, `isAt(Class)` and `queryParameter(String)` on the
  base class. They read `location.href`, so they already see a `pushState`
  navigation.
- `VaadinClient.uiId(page)`, the Vaadin UI id of the page (#280).
- `GridElement.getColumns()` and `isSelectionColumn(int)`, to convert to Flow's
  column indexes (#281); `getHeaderContentLocator(int)` and
  `getFooterContentLocator(int)`, one locator across every header or footer row
  (#282).
- `RadioButtonElement` is public, with the usual factories and a typed query
  (#255); `AccordionElement.get(..)`, `TabSheetElement.get(Locator)`,
  `SplitLayoutElement.get(Locator)` and `DetailsElement.getBySummaryText(Locator, ..)`
  (#261).
- `VaadinElement.getLightDomChildren(..)` / `getLightDomDescendants(..)` (#272).

## Fixes

- `AbstractNumberFieldElement.getHasControls()` returned `false` while the step
  buttons were shown (#256).
- `IntegerFieldElement` / `NumberFieldElement` `getMin()` / `getMax()` threw on a
  field without a bound; `getPlaceholder()` and `getAllowedCharPattern()` threw
  when unset. They return `null` (#257).
- `MessageListElement.assertMessageText` retries like the other assertions (#258).
- Javadoc that described behaviour the code does not have (#260).
