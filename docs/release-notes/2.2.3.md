# DramaFinder 2.2.3

DramaFinder 2.2.3 makes the selection methods of the multi-select combo box
and the list box do what their names say.

## Upgrading from 2.2.2

One behaviour differs:

- **`MultiSelectComboBoxElement.selectItem` no longer deselects** (#321).
  `selectItem(s)`, `deselectItem(s)` and `filterAndSelectItem` used to click
  the item whatever its state, so selecting a selected item deselected it and
  deselecting an unselected one selected it. They now skip an item that is
  already in the requested state. A test that relied on the click toggling
  should call the new `toggleItem(label)`.
- **`ListBoxElement.selectItem` no longer deselects** (#322). In multiple
  mode it clicked the item whatever its state, so selecting a selected item
  deselected it. It now skips an item that is already selected. Call the new
  `deselectItem(label)` or `toggleItem(label)` instead.

## New

- **`MultiSelectComboBoxElement.isSelected(label)`,
  `assertItemSelected(label)` and `assertItemNotSelected(label)`** (#321)
  read one item's selection from `selectedItems`, so the overlay can stay
  closed. See [MultiSelectComboBoxElement](../specifications/MultiSelectComboBoxElement.md#reading-the-items-and-the-selection).
- **`MultiSelectComboBoxElement.toggleItem(label)`** (#321) clicks the item
  as a user does, toggling its selection.
- **`ListBoxElement.deselectItem(label)`, `toggleItem(label)`,
  `isSelected(label)`, `assertItemSelected(label)` and
  `assertItemNotSelected(label)`** (#322). `deselectItem` skips an item that is
  not selected; on a single-mode list box a click never deselects, so the item
  stays selected. See [ListBoxElement](../specifications/ListBoxElement.md#multiple-selection).
