# DramaFinder 2.2.2

DramaFinder 2.2.2 makes the wait after an action one browser call again.

## Upgrading from 2.2.1

No source changes are needed. One behaviour differs:

- **The wait after an action has its own 30-second limit** (#313). It used
  to fail after the page's default timeout (`page.setDefaultTimeout(..)`,
  15 seconds in `AbstractBasePlaywrightIT`); it now runs inside the page,
  where that timeout does not apply, and fails with a `TimeoutError` when
  Flow is still busy after 30 seconds.

## Fixes

- **The wait after an action is one browser call again** (#313). 2.2.1 added
  a second call to wait for a server-side navigation (#304), so every action
  and every `navigate(..)` paid one more round trip to the browser. The idle
  and navigation checks now run in one script that loops in the page. It
  also checks again one task after it finds Flow settled, so a navigation
  that starts just after the client goes idle is still waited for. A
  navigation that never completes still releases the wait after two seconds.
  See [Actions and waiting](../guide/actions-and-waiting.md#navigation-waits-too).
- **`assertAt` and `isAt` match a view's `@RouteAlias` paths** (#318). They
  only matched the `@Route` template, so a view shown at one of its aliases
  (e.g. Bakery's storefront at the root `""`) was reported as not there. Each
  alias now matches with the same template rules as the route, under the
  `@RoutePrefix` of its own `layout`. See
  [Navigation](../guide/navigation.md#asserting-where-the-browser-is).
