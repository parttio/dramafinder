# DramaFinder 2.0.0

DramaFinder 2.0 makes lookups strict and actions synchronous with the server:

- label lookups match the whole label;
- every action waits for the Vaadin round-trip it triggers;
- a typed query builder gives every element the same lookup grammar;
- the Spring Boot base class ships in the library.

1.x test suites **compile unchanged**, unless a test class declares its own
`navigate`, `assertAt`, `assertPath` or `assertQueryParameter` (see below). Lookups
that pass part of a label fail at runtime, as does a test that asserts a state
while a request is still in flight.
Read the **[migration guide](../../src/main/resources/META-INF/dramafinder/MIGRATION-2.0.md)**
before upgrading. The jar also ships it, at `META-INF/dramafinder/MIGRATION-2.0.md`.

## Breaking changes

### Label lookups match exactly by default (#207)

Every factory that finds a component by its label, text, header, title or name now
matches the **whole** value, case-sensitively (whitespace-normalized), and applies
no `.first()`. `TextFieldElement.getByLabel(page, "Name")` no longer resolves to a
`"Nickname"` field, and two components sharing a label raise a Playwright
strict-mode error instead of resolving to the first one in the DOM.

Partial matching is now explicit: `getByLabelContaining(Page|Locator, String)` next
to every `getByLabel`, and `ButtonElement.getByTextContaining(Page|Locator, String)`.
Both are case-insensitive substring matches, still without `.first()`.

52 public factory methods change. **P** = 1.x matched part of the label, **C** =
1.x matched a differently-cased label, **D** = 1.x picked the first of several
matches.

**Field `getByLabel` — P C D** (label, `aria-label` or placeholder; replacement
`getByLabelContaining`), on `Page` and `Locator` unless noted:

- `BigDecimalFieldElement`, `ComboBoxElement`, `DatePickerElement`,
  `DateTimePickerElement`, `EmailFieldElement`, `IntegerFieldElement`,
  `MultiSelectComboBoxElement`, `NumberFieldElement`, `SelectElement`,
  `SliderElement`, `TextAreaElement`, `TextFieldElement`, `TimePickerElement`
  — `getByLabel(Page, String)` and `getByLabel(Locator, String)` (26 methods)
- `PasswordFieldElement.getByLabel(Page, String)`
- `SelectElement.getByLabel` now matches the visible label or `aria-label`, and has
  no placeholder fallback. The 1.x lookup matched the value button's name, which
  includes the selected value, so it broke after a selection.

**Other `getByLabel`** (replacement `getByLabelContaining`):

- P C D: `BreadcrumbsElement.getByLabel(Page, String)`,
  `CheckboxElement.getByLabel(Page, String)`,
  `CheckboxGroupElement.getByLabel(Page|Locator, String)`,
  `CustomFieldElement.getByLabel(Page|Locator, String)` (also behind
  `CustomFieldElement.getField(Class, String)`),
  `ListBoxElement.getByLabel(Page, String)`,
  `RadioButtonGroupElement.getByLabel(Page, String)`,
  `SideNavigationElement.getByLabel(Page, String)`,
  `SwitchElement.getByLabel(Page, String)`
- P C: `ButtonElement.getByLabel(Page, String)`,
  `MenuBarElement.getByLabel(Page, String)`, `MenuElement.getByLabel(Page, String)`,
  `PopoverElement.getByLabel(Page, String)`

**Button text — P C** (replacement `getByTextContaining`):
`ButtonElement.getByText(Page, String)`, `ButtonElement.getByText(Locator, String)`.
The name is the `aria-label`, or else the button's own text. An open tooltip is no
longer part of it; in 1.x the lookup stopped matching after a hover.

**Headers, titles, summaries, button text** (no `…Containing` variant):

- P C: `DialogElement.getByHeaderText(Page, String)`,
  `ConfirmDialogElement.getByHeaderText(Page, String)`,
  `LoginOverlayElement.getByTitle(Page, String)`,
  `CardElement.getByTitle(Page|Locator, String)`,
  `DetailsElement.getBySummaryText(Page, String)` (now the summary's accessible
  name)
- P C D: `UploadElement.getByButtonText(Page, String)`

**Avatar name — D only:** `AvatarElement.getByName(Page|Locator, String)`.

`AccessibleNameLocator.find(...)` (utility class) is exact too.
`AccessibleNameLocator.findContaining(...)` keeps the 1.x matching, without
`.first()`.

These keep their 1.x matching: `BadgeElement.getByText`,
`NotificationElement.getByText`, `TooltipElement.getByText` and
`VirtualListElement.getItemByText` (documented "contains" helpers). So do the item
lookups inside containers, which were already exact since 1.2.0.

### Actions wait for the Vaadin server round-trip (#209)

Every element action that can reach the server now returns only once Vaadin Flow
has no request in flight. This covers `click`, `setValue`, `clear`,
`check`/`uncheck`, `selectItem`, key presses, `hoverTarget`, `focus`/`blur`,
`upload`, `setProperty` and the rest. A getter called right after an action reads
the state the server produced. In 1.x only `setValue` and a few date, slider and
checkbox-group methods waited.

A test that asserts the in-flight state (a loading indicator, a
disabled-while-saving button) now sees the final state. Wrap that action in
`AutoWait.withoutWaiting(() -> ...)`, or pass `-Ddramafinder.autoWait=false` to
restore the 1.x timing for a whole run. An explicit `waitForVaadinIdle()` always
waits; call it after actions on a raw Playwright `Locator`.

The full suite ran about 7 % longer: an idle check is a single quick evaluation in
the page.

### New protected methods on `AbstractBasePlaywrightIT` (#211)

`AbstractBasePlaywrightIT` gains `navigate(Class<?>)`, `navigate(Class<?>, Object)`,
`assertAt(Class<?>)`, `assertPath(String)` and `assertQueryParameter(String, String)`
(see "Navigation by route class"). A test class that already declares a method with
one of these names and parameter types now overrides it. If the return type differs,
or the method is less visible than `protected`, the class no longer compiles. Rename
the test's own method, or drop it in favour of the inherited one.

## New features

### Typed query builder (#206)

One lookup grammar for every element, alongside the factories:

```java
import static org.vaadin.addons.dramafinder.element.query.ElementQueries.find;

TextFieldElement name = find(page, TextFieldElement.class).withLabel("Name").single();
dialog.find(ButtonElement.class).withText("Delete").single().click();
find(page, ButtonElement.class).withLabel("Save"); // does not compile
```

- Each element offers only the filters that fit it, checked at compile time:
  `withLabel` / `withLabelContaining` on labelled components,
  `withText` / `withTextContaining` on buttons, tabs, badges and similar,
  `withPlaceholder` on input fields.
- Every element has `withId`, `withTestId`, `withAttribute`, `withClassName`,
  `withAccessibleName` and a `refine(...)` escape hatch.
- Terminals: `single()` (strict), `first()`, `get(int)`, `all()`, `count()`,
  `exists()`, `getLocator()`. Queries are immutable and stay lazy.
- Text filters read the component's own text. Slotted icons, tooltips and
  shadow-rendered numbers are left out, so a badge with an icon matches its text.
- `withAccessibleName` never matches through a nested component: a dialog is not
  found by the name of a field it holds.
- Custom components join by implementing `Findable<Q>` with a query type.

### `getById` and `getByTestId` on every element (#210)

The id and test-id factories now exist on 52 elements, each with a `Page` and a
`Locator` overload: `getById(page, "save")` and `getByTestId(page, "save-button")`.
In 1.x `getById` existed only on AppLayout, FormLayout, Grid, TreeGrid and Tabs.

- The test id is the `data-testid` attribute that Flow's `Component.setTestId(...)`
  sets.
- Matches are exact, limited to the element's own tag, and fail on duplicates.
- They are fallbacks for components without a user-visible name.
- The five 1.x `getById` methods now also check the tag, and accept ids that are
  not valid CSS identifiers.
- Not offered on Notification, Tooltip, Menu, ContextMenu and MenuItem, whose
  wrapped tag is not where Flow puts the id.

### Navigation by route class (#211)

`AbstractBasePlaywrightIT` navigates by view class instead of a hand-built URL, and
asserts where the browser is, retrying until it gets there:

```java
navigate(ProfileView.class);                                        // nav/profile
navigate(ArticleView.class, 42);                                    // HasUrlParameter
navigate(UserEditView.class, new RouteParameters("userId", "42")); // user/:userId/edit
assertAt(ProfileView.class);           // e.g. after a login redirect or a guard
assertPath("nav/profile");
assertQueryParameter("tab", "2");      // null asserts the parameter is absent
```

- The path comes from `@Route`, or Flow's naming convention when it has no value. It
  is prefixed by the `@RoutePrefix` of the route's layout and its `@ParentLayout`
  chain, honouring `absolute`. So a renamed route breaks at the `navigate` call, not
  silently.
- `navigate` waits for Vaadin to finish loading. `assertAt` accepts any value for a
  template's parameters or a `HasUrlParameter`.
- `RouteNavigation` offers the same with an explicit `Page` and base URL, for tests
  that do not extend `AbstractBasePlaywrightIT`.
- `com.vaadin:flow-server` is a `provided` dependency: only tests that navigate by
  class need it. `AbstractBasePlaywrightIT` still loads without it.

### Spring Boot base class in the library (#212)

`org.vaadin.addons.dramafinder.spring.SpringPlaywrightIT` replaces the class that
each Spring Boot project copied from the skill's template:

```java
public class OrderViewIT extends SpringPlaywrightIT {   // no annotation needed
    @Override
    public String getView() {
        return "orders";
    }
}
```

- It carries `@SpringBootTest(webEnvironment = RANDOM_PORT)`. Re-annotate the test
  to change properties or the web environment (`DEFINED_PORT` works too).
- `getUrl()` comes from the running server: the local port, the servlet context
  path, and `https` when `server.ssl.enabled` is set.
- **Spring stays optional.** DramaFinder declares `spring-boot-test` as `provided`,
  so it never adds Spring to a project's classpath. Projects without Spring keep
  extending `AbstractBasePlaywrightIT`. A Spring Boot project already has
  `spring-boot-starter-test`.
- A project's own `SpringPlaywrightIT` copy keeps working. Delete it and switch the
  imports to `org.vaadin.addons.dramafinder.spring.SpringPlaywrightIT`, then drop
  the now-redundant `@SpringBootTest(webEnvironment = RANDOM_PORT)` from the tests.

## Improvements

- **`ViewOutline`** suggests `getByTestId` for a component without a label, before
  falling back to `getById`. It no longer annotates ambiguous lookups as
  substring matches, because labels now match in full (#207, #210).
- **`ButtonQuery` / `TextQuery`** gain `withAccessibleNameContaining(String)`
  (#207).

## Fixes

Found while making lookups exact (#207):

- `SelectElement.getByLabel` stopped finding the select once a value was picked.
- `DetailsElement.getBySummaryText` missed summaries whose text sits in a `<span>`.
- `ButtonElement.getByText` and `ButtonQuery.withAccessibleName` stopped matching a
  button while its tooltip was open.
