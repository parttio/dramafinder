# DramaFinder 2.2.1

DramaFinder 2.2.1 makes `getText()` leave out tooltips, so a component reports
the same text a `withText(..)` query found it by.

## Upgrading from 2.2.0

No source changes are needed. One behaviour differs:

- **`VaadinElement.getText()` leaves out tooltips** (#301). A tooltip set with
  `setTooltipText(..)` is a `vaadin-tooltip` child of the component it
  describes, and `getText()` used to return its text with the component's own:

  ```java
  Button save = new Button("Save");
  save.setTooltipText("Saves the form");
  ```

  ```java
  ButtonElement button = find(page, ButtonElement.class).withText("Save").single();
  button.getText();        // 2.2.0: "SaveSaves the form"   2.2.1: "Save"
  button.getTooltipText(); // "Saves the form"
  ```

  The text of every `vaadin-tooltip` inside the component is left out, at any
  depth, so a card or layout holding a button with a tooltip no longer reports
  that tooltip either. Everything else stays: slotted text such as a card's
  title or a prefix, and the text of child components. Whitespace is still
  returned as the DOM holds it. A test that asserted the concatenated text now
  fails; assert the component's text and the tooltip separately.

  `getText()` returns an empty string for a component without text, never
  `null`.

  Elements that read a narrower text keep doing so: `BadgeElement`,
  `TooltipElement`, `MarkdownElement` and `GridElement.CellElement` override
  `getText()` and are unchanged.

## Documentation

- `docs/specifications/VaadinElement.md` and the `getText()` Javadoc say what
  the method reads, and how that differs from browserless tests: there, Flow's
  `Element.getText()` reads only a component's own text nodes, so
  `new Div(new Span("Hello"))` reads `""` server-side and `"Hello"` in the
  browser.
